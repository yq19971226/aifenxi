# Axiom 线上宝塔部署与容器说明

本文面向首次在服务器（含宝塔面板或纯 Linux）上部署 Axiom 的完整步骤，包含：必须启动的服务、脚本与定时任务、管理员账户创建、环境变量与 Nginx 等。按顺序执行即可完成上线。

---

## 一、服务器与域名准备

1. **服务器**：建议 Ubuntu 22.04 LTS，至少 2 核 4G；若用宝塔，先安装宝塔再按下面步骤操作。
2. **域名**：准备一个已解析到本机 IP 的域名（如 `app.yourdomain.com`），A 记录指向服务器公网 IP。
3. **代码目录**：约定项目放在 `/opt/axiom`（与 `server-init.sh` 一致）；若改目录，后文所有 `/opt/axiom` 需替换成你的路径。

---

## 二、必须启动的服务清单（缺一不可）

| 服务 | 说明 | 如何启动 |
|------|------|----------|
| **PostgreSQL** | 主数据库 | Docker 容器 `postgres` |
| **Redis** | 缓存与 Celery 队列 | Docker 容器 `redis` |
| **backend** | 后端 API (FastAPI) | Docker 容器 `backend` |
| **worker** | Celery 异步任务 | Docker 容器 `worker` |
| **beat** | Celery 定时任务调度 | Docker 容器 `beat` |
| **frontend** | 前端 (Next.js) | Docker 容器 `frontend` |
| **部署代理** | 一键更新/回退用，宿主机进程 | systemd 服务 `axiom-deploy-agent` |

说明：

- 前 6 项由 **Docker Compose** 一起启动。
- 部署代理是**宿主机**上的 Python 服务，监听 `127.0.0.1:9321`，供后端容器通过 `host.docker.internal:9321` 调用，用于管理后台「一键更新」「一键回退」。

---

## 三、首次部署：一步步做

### 3.1 上传代码到服务器

将本仓库克隆或上传到 `/opt/axiom`：

```bash
# 若已有 git（推荐）
sudo git clone https://你的仓库地址 /opt/axiom
cd /opt/axiom
```

或使用宝塔「文件」上传压缩包后解压到 `/opt/axiom`。

### 3.2 运行一键初始化脚本（推荐）

脚本会安装 Docker、Docker Compose、Nginx、Certbot，配置防火墙、Nginx 反向代理、SSL、以及部署代理 systemd 服务。

```bash
sudo bash /opt/axiom/scripts/server-init.sh 你的域名
# 示例：sudo bash /opt/axiom/scripts/server-init.sh app.yourdomain.com
```

执行完成后会：

- 生成 `/opt/axiom/.env`（若不存在），并写入随机 JWT 密钥与数据库密码、生产 API 地址等。
- 将 Nginx 配置替换为你的域名。
- 启用并启动 **axiom-deploy-agent** 服务（部署代理）。

若未用该脚本，请至少保证：

- 已安装 Docker 与 Docker Compose。
- 已配置 Nginx 反向代理到 `127.0.0.1:8000`（API）和 `127.0.0.1:3000`（前端），并配置 SSL。
- 已按下一节配置 `.env` 并启动部署代理。

### 3.3 配置环境变量 .env

若未运行 `server-init.sh`，需手动复制并编辑：

```bash
cp /opt/axiom/.env.example /opt/axiom/.env
nano /opt/axiom/.env   # 或用宝塔「文件」编辑
```

**必须修改或确认的项：**

| 变量 | 说明 | 示例 |
|------|------|------|
| `POSTGRES_PASSWORD` | 数据库密码 | 强随机字符串（脚本会生成） |
| `JWT_SECRET_KEY` | JWT 密钥 | 强随机字符串（脚本会生成） |
| `APP_ENV` | 环境 | `production` |
| `PUBLIC_API_URL` | **前端构建时**写入的 API 根地址（浏览器请求会发到这里） | `https://www.axiom123.cc`（必须与 Nginx 对外域名一致，不要用 `http://backend:8000`） |
| `NEXT_PUBLIC_WS_URL` | **前端构建时**写入的 WebSocket 地址 | `wss://www.axiom123.cc`（与域名一致，协议为 wss） |
| `DEPLOY_AGENT_URL` | 部署代理地址（后端用） | `http://host.docker.internal:9321` |
| `DEPLOY_AGENT_TOKEN` | 可选，与部署代理校验 | 若部署代理设置了 token，此处填相同值 |

> **重要**：`PUBLIC_API_URL` 和 `NEXT_PUBLIC_WS_URL` 会在 **构建前端镜像** 时写进静态资源。修改 `.env` 后必须**重新构建前端**并重启，否则登录等请求仍会发到旧地址导致 404。见下文「重新构建前端」。

数据库连接：在 Docker 内使用服务名，例如：

- `DATABASE_URL=postgresql+asyncpg://omnimind:你的密码@postgres:5432/omnimind`
- `REDIS_URL=redis://redis:6379`

`server-init.sh` 已按此方式生成过则可不动。

### 3.4 启动所有 Docker 服务

```bash
cd /opt/axiom
docker compose -f docker-compose.yml -f docker-compose.prod.yml up -d
```

> 若单机资源紧张，可编辑 `docker-compose.prod.yml`，将 `worker` 的 `replicas: 2` 改为 `1`（或删除该行，默认 1 个）。

等待约 1～2 分钟，检查容器是否都在运行：

```bash
docker compose -f docker-compose.yml -f docker-compose.prod.yml ps
```

应看到 `postgres`、`redis`、`backend`、`worker`、`beat`、`frontend` 均为 `Up` 且健康。

### 3.4.1 修改域名或 API 地址后：重新构建前端（必做）

前端在**构建时**会把 `PUBLIC_API_URL` 和 `NEXT_PUBLIC_WS_URL` 写进静态资源，运行时无法再改。若你修改了 `.env` 里的 `PUBLIC_API_URL` 或 `NEXT_PUBLIC_WS_URL`（例如从测试域名改为正式域名），必须**重新构建前端镜像**并重启，否则登录等请求会发到错误地址，出现「Not Found」或 404。

在服务器上执行：

```bash
cd /opt/axiom
# 确认 .env 中已设置：PUBLIC_API_URL=https://www.axiom123.cc 与 NEXT_PUBLIC_WS_URL=wss://www.axiom123.cc
docker compose -f docker-compose.yml -f docker-compose.prod.yml build --no-cache frontend
docker compose -f docker-compose.yml -f docker-compose.prod.yml up -d
```

构建完成后访问 `https://你的域名`，应能打开首页；登录请求会发往 `https://你的域名/api/auth/login`，由 Nginx 反代到后端。

### 3.5 启动部署代理（宿主机）

若已运行过 `server-init.sh`，部署代理已启用并启动。否则需手动安装 systemd 服务：

```bash
sudo cp /opt/axiom/scripts/axiom-deploy-agent.service /etc/systemd/system/
# 若项目不在 /opt/axiom，先编辑该文件中的 WorkingDirectory 与 ExecStart 路径
sudo systemctl daemon-reload
sudo systemctl enable axiom-deploy-agent
sudo systemctl start axiom-deploy-agent
sudo systemctl status axiom-deploy-agent   # 确认 active (running)
```

部署代理监听 `127.0.0.1:9321`，仅本机可访问，用于管理后台「一键更新」「一键回退」。

### 3.6 创建后台管理员账户（必须）

首次部署后必须至少创建一个管理员账号，否则无法登录管理后台。

**方式一：在容器内交互式输入（推荐）**

```bash
cd /opt/axiom
docker compose -f docker-compose.yml -f docker-compose.prod.yml exec backend python scripts/create_admin.py
```

按提示输入邮箱和密码（密码至少 8 位）。

**方式二：环境变量（适合脚本/CI）**

```bash
docker compose -f docker-compose.yml -f docker-compose.prod.yml exec -e ADMIN_EMAIL=admin@你的域名.com -e ADMIN_PASSWORD=你的强密码 backend python scripts/create_admin.py
```

创建成功后终端会输出 `Admin account ready: 你的邮箱`。使用该邮箱和密码登录管理后台即可。

## 四、脚本与「自动运行」说明

### 4.1 哪些脚本需要「自动运行」？

- **不需要 cron 定时拉代码**：日常更新使用管理后台「系统管理 → 一键更新」即可（会调部署代理执行 `deploy.sh`，内部会 `git pull` 再构建并重启容器）。
- **需要长期运行的服务**：
  - **Docker 容器**：通过 `docker compose up -d` 已设为开机自启（若未改配置）。
  - **部署代理**：通过 `systemctl enable axiom-deploy-agent` 已设为开机自启。

### 4.2 一键更新时发生了什么？

当你在管理后台点击「一键更新」时：

1. 后端请求宿主机上的部署代理 `http://host.docker.internal:9321`。
2. 部署代理执行 `scripts/deploy.sh`（默认拉当前分支最新代码，再 `docker compose build` 与 `up -d`）。
3. 部署过程以 SSE 流式返回日志到前端。

因此「自动运行」的只是**这两个**：

- Docker Compose 管理的 6 个服务（postgres、redis、backend、worker、beat、frontend）。
- 宿主机上的 **axiom-deploy-agent**（监听 9321）。

### 4.3 可选：SSL 证书自动续期

若使用 Let's Encrypt 且通过 `server-init.sh` 或 `certbot --nginx` 配置过，一般已启用 certbot 定时任务：

```bash
sudo systemctl status certbot.timer   # 查看是否启用
```

无需额外脚本。

### 4.4 可选：数据库备份定时任务

若存在 `scripts/backup_db.sh`，可自行用 cron 定期备份，例如每天凌晨 2 点：

```bash
0 2 * * * cd /opt/axiom && bash scripts/backup_db.sh
```

非必须，按需添加。

## 五、端口与 Nginx 约定

- **宿主机端口**（仅本机或 Nginx 使用，不对外直接暴露）：
  - `127.0.0.1:8000` — 后端 API
  - `127.0.0.1:3000` — 前端
  - `127.0.0.1:9321` — 部署代理（仅本机）
- **对外**：只开放 80/443，由 Nginx 反向代理到 8000（API）和 3000（前端）。  
- 项目自带 `nginx/axiom.conf` 模板，`server-init.sh` 会按域名替换并写入 `/etc/nginx/sites-available/axiom`。若你使用宝塔，可在宝塔里新建「网站」，反向代理到 `127.0.0.1:8000`（/api 与 /ws）和 `127.0.0.1:3000`（/），并配置 SSL。
- **宝塔 /api 代理注意**：`proxy_pass` 不要写末尾斜杠，应写 `proxy_pass http://127.0.0.1:8000;`。若写成 `http://127.0.0.1:8000/`，Nginx 会把路径里的 `/api` 去掉再转发，后端收到的是 `/auth/login` 而非 `/api/auth/login`，会 404。

## 六、健康检查与排错

- 后端健康：`curl -s http://127.0.0.1:8000/health` 应返回 `{"status":"ok"}`。
- 前端：浏览器访问 `https://你的域名/dashboard` 应能打开（或重定向到登录）。
- 部署代理：`curl -s http://127.0.0.1:9321/health` 应返回 200（若代理带 token，需在请求头或参数中带上）。

若一键更新失败，可到服务器执行：

```bash
cd /opt/axiom
bash scripts/deploy.sh
```

查看终端输出或 `logs/deploy-*.log` 定位问题。

## 七、完整交付清单（自检）

- [ ] 代码在 `/opt/axiom`（或你约定的目录）
- [ ] `.env` 已配置且含生产用 JWT、数据库密码、域名相关 URL
- [ ] `docker compose -f docker-compose.yml -f docker-compose.prod.yml up -d` 已执行，6 个容器均 Up
- [ ] `axiom-deploy-agent` 服务已 enable 且 start，监听 9321
- [ ] 已通过 `create_admin.py` 创建至少一个管理员账户
- [ ] Nginx 反向代理 80/443 → 8000（API）/ 3000（前端），并已配置 SSL
- [ ] 能通过 https://你的域名 访问前端并登录管理后台
- [ ] 管理后台「API 密钥」等业务配置在后台完成，敏感密钥不写进 .env（按项目约定）

按上述清单逐项确认后，即可视为上线交付完成。后续日常发版使用「系统管理 → 一键更新」或 SSH 执行 `scripts/deploy.sh` 即可。

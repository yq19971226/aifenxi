# 手机端与综合分析体验 — 多视角联合审查

基于当前代码与截图的联合审查结论，含产品、UX、前端、视觉、数据五方视角的争论与收敛方案。

---

## 一、综合分析：模式选中不明显（超短线/日内博弈/趋势策略）

**现状（代码）**  
- `consensus/page.tsx` 第 96–102 行：选中态为 `ring-1 ring-indigo-500/50 bg-indigo-500/[0.05]`，未选中为透明底 + 白边。  
- 移动端小屏、强光下对比度不足，易与「未选中」混淆。

**视角争论**  
- **产品**：必须一眼能看出当前模式，否则会误以为没选上、重复点击或误操作。  
- **视觉**：保留 indigo 体系可接受，但需提高「选中」权重：要么加深背景，要么加左边框/角标。  
- **前端**：不动大结构，只加强 class，成本低。

**收敛方案**  
- 选中态增强：在现有基础上增加其一或组合  
  - 左侧竖条：`border-l-2 border-l-indigo-500`（或 `rounded-l` 仅左侧圆角）  
  - 背景加深：`bg-indigo-500/[0.12]` 替代 `/[0.05]`  
  - 可选角标：右上角小标签「当前」或勾选图标  
- 修改位置：`app/[locale]/(main)/consensus/page.tsx` 中 `MODE_CONFIGS.map` 的 `button` 的 `className`，并为选中项增加角标或左侧条。

## 二、综合分析：选币种界面纯白（低端感）

**现状（代码）**  
- `SymbolSelector`（`components/layout/SymbolSelector.tsx`）使用原生 `<select>`。  
- 移动端浏览器会弹出**系统原生选择器**（如 Android 为白底列表），与整站深色主题脱节，显得「纯白、低端」。

**视角争论**  
- **产品**：选币是高频入口，第一印象很重要，必须与产品调性一致。  
- **UX**：原生 select 可访问性好，但视觉不可控；自定义控件需保证焦点、键盘、读屏。  
- **前端**：用自定义下拉/底 sheet 替代原生 select，移动端优先 sheet（从底滑出），桌面可保留下拉。

**收敛方案**  
- 不再在移动端使用原生 `<select>` 弹层。  
- 实现「自定义选币控件」：  
  - **移动端**：点击当前币种 → 底部弹出 sheet（`fixed bottom-0 inset-x-0`），列表深色背景（如 `bg-[#0f1117]`）、与顶栏一致圆角，选项带勾选/高亮当前项。  
  - **桌面端**：可保留下拉或同风格的下拉列表（深色背景）。  
- 组件仍为 `SymbolSelector`，内部根据 `window.innerWidth` 或 CSS 媒体查询切换「原生 select」与「自定义 sheet/下拉」；或统一改为自定义，仅用 listbox 角色与 aria 保持可访问性。

## 三、手机端侧栏：一二级自动展开与选中不明显

**现状（代码）**  
- `TopNav.tsx` 第 586–624 行：有子项时，父级为普通 `div`，子级全部平铺展示，无折叠。  
- 用户反馈「一二级自动展开不协调」：希望父级可折叠，或至少视觉上主次分明。  
- 当前选中态：`text-zinc-100 bg-white/[0.06]`，在深色底上对比弱。

**视角争论**  
- **产品**：侧栏是主导航，当前页必须一目了然；展开方式可接受「默认展开」但要有明显当前项。  
- **UX**：若保留全部展开，需通过缩进、字重、颜色强烈区分「当前项」；若改为折叠，则默认只展示一级，点击再展二级。  
- **前端**：折叠需加状态（如 `openKeys`），并做动画；加强选中态可先做，成本低。

**收敛方案**  
- **优先**：加强当前项识别  
  - 当前页对应项：左侧竖条 `border-l-2 border-l-indigo-500` + 背景 `bg-indigo-500/10` 或 `bg-white/[0.08]`，字色 `text-white`。  
  - 可选：在项右侧加「当前」小字或勾选图标（仅当前项）。  
- **可选（后续）**：一级收合  
  - 有子项的一级项为可点击，点击切换展开/收起；无子项仍为 Link。  
  - 默认可保持「当前路径所在分组展开、其余收起」以减少一屏信息量。

## 四、仪表盘：机会排行多币种时布局乱

**现状（代码）**  
- `OpportunityRank` 为纵向 `space-y-2` 列表，外层与 `RiskRadar` 同处 `grid grid-cols-1 lg:grid-cols-2`。  
- 移动端为单列，机会排行在上、风险雷达在下；当可操作币种多时，卡片变长，且无最大高度，整屏被占满，显得「乱」。

**视角争论**  
- **产品**：机会排行是入口，但要控制一屏信息量，多时应收敛为「前 N 个 + 更多」。  
- **UX**：列表建议设最大高度 + 内部滚动，或移动端只展示前 3–5 条 +「查看更多」跳共识/列表页。  
- **前端**：`OpportunityRank` 容器加 `max-h-[某值] overflow-y-auto`，或对列表 slice 前 5 条，加「查看全部」链接。

**收敛方案**  
- 机会排行卡片：  
  - 移动端：列表容器 `max-h-[280px] sm:max-h-[320px] overflow-y-auto`，保证与下方风险雷达、表格不会挤爆一屏。  
  - 可选：仅展示前 5 条，超出显示「共 N 个可操作 · 查看全部」链接到共识页或带 symbol 过滤的列表。  
- 修改位置：`components/dashboard/OpportunityRisk.tsx` 中 `OpportunityRank` 的列表容器。

## 五、仪表盘：信号来源与联动性

**现状（代码与接口）**  
- `backend/app/api/dashboard_overview.py`：概览数据来自 Redis `strategy:latest:{symbol}` 等，为**系统级最新一条**（任一用户触发分析后写入），非「当前用户私有」也非「全用户聚合」。  
- 前端仪表盘点击币种可跳 `consensus?symbol=XXX`，可再跑一次分析，此为「联动」。

**视角争论**  
- **产品**：用户需知道「看到的是系统最新结果」还是「自己的结果」；若为系统最新，需在文案中说明，避免误解。  
- **数据**：当前设计是「每币种一条最新策略」，不做按用户过滤；若未来要做「我的分析」需另做 key 或接口。  
- **UX**：仪表盘与共识页的联动可更显性：如「点击跳转可刷新该币种分析」「数据说明」小字。

**收敛方案**  
- **前端**：在仪表盘概览区域增加一句简短说明（可放 SummaryCards 上方或表格上方），例如：  
  - 「信号与机会基于系统最新分析结果，点击币种可进入共识页刷新分析。」  
- **产品/后端**：若确认长期为「系统最新」则保持现状；若需「我的分析」再单独做接口与入口。

## 六、首页：内容偏左、右边不协调

**现状（代码）**  
- 落地页各 section 使用 `mx-auto max-w-6xl px-4 sm:px-6` 或 `max-w-4xl`，内容居中。  
- Hero 为 `grid lg:grid-cols-[1fr,420px]`，大屏左侧文案、右侧 mockup；小屏右侧隐藏，仅左侧一列，整体左对齐。  
- 用户感受「偏左、右边不协调」可能来自：小屏下整页只有一列且靠左；或大屏下某块内容未真正居中/右侧留白过大。

**视角争论**  
- **视觉**：希望整站有明确中轴与平衡感，避免「整页左重右轻」。  
- **UX**：移动端单列居中即可；桌面端可检查每 section 是否都是 `max-w-* mx-auto` 且无多余 `ml-*`。  
- **前端**：统一 section 为 `text-left`（或保持）但容器 `mx-auto`；Hero 小屏可加 `text-center` 或保持左对齐但保证容器居中。

**收敛方案**  
- 检查所有 landing section 的根容器是否为 `mx-auto` + `max-w-*`，无单侧 margin 导致整体偏移。  
- Hero 移动端：若希望更平衡，可将标题/副标题改为 `text-center`，CTA 按钮 `justify-center`；或保持左对齐，仅保证容器居中。  
- 修改位置：`app/[locale]/landing-sections.tsx` 各 section 的 wrapper 与 Hero 内部对齐类。

## 七、实施优先级建议

# 干净提交与上传到仓库 — 小白向说明

本文说明如何把当前项目「干净地」提交到 Git 并推送到远程仓库（如 GitHub / Gitee），适合不熟悉 Git 的同学按步骤操作。

---

## 一、提交前自检（避免把不该传的传上去）

### 1.1 不要提交的内容

- **`.env`**：里面是密码、JWT 密钥等，绝不能提交。仓库里应只有 `.env.example`。
- **`node_modules/`**、**`__pycache__/`**、**`.next/`**、**`*.pyc`**：依赖或构建产物，一般不提交。
- **`logs/`**、**`.cursor/`**、**`.idea/`** 等本地/日志目录：若不想上传，应被 `.gitignore` 忽略。

### 1.2 确认 .gitignore 已包含这些

打开项目根目录的 `.gitignore`，确认包含类似内容（若没有就加上）：

```
.env
.env.local
*.log
logs/
node_modules/
.next/
__pycache__/
*.pyc
.idea/
.cursor/
```

保存后，这些文件/目录就不会被 `git add` 进去。

## 二、第一次使用本仓库（克隆与远程）

若你是**从零开始**，还没有把代码放到任何远程仓库：

### 2.1 在 GitHub / Gitee 上新建仓库

- GitHub：打开 https://github.com/new ，仓库名随意（如 `aifenxi`），不要勾选「Initialize with README」。
- Gitee：类似，新建仓库，不初始化。

记下仓库地址，例如：
- `https://github.com/你的用户名/aifenxi.git`
- 或 `git@github.com:你的用户名/aifenxi.git`（SSH）

### 2.2 本地已有项目，要推上去

在项目根目录（如 `d:\aifenxi`）打开终端（PowerShell 或 CMD），执行：

```bash
# 若还没初始化过 git（一般已有）
git init

# 添加远程仓库（把下面地址换成你的）
git remote add origin https://github.com/你的用户名/aifenxi.git
# 若已存在 origin 但地址错了，可：git remote set-url origin 新地址
```

若项目本来就是 clone 下来的，通常已有 `origin`，可跳过上面，直接看「三、日常提交与推送」。

## 三、日常提交与推送（干净提交）

### 3.1 看当前改了哪些文件

```bash
cd d:\aifenxi
git status
```

会列出「已修改」「未跟踪」的文件。确认没有 `.env`、`node_modules` 等再继续。

### 3.2 把要提交的文件加入暂存区

**方式 A：全部添加（推荐先确认 status 无误）**

```bash
git add .
```

**方式 B：只加指定文件/目录**

```bash
git add backend/app frontend/app docs/
```

### 3.3 提交到本地仓库

```bash
git commit -m "简短说明你做了什么，例如：上线前修复：补充 v12-v17 迁移、创建管理员脚本与部署文档"
```

- 一条 commit 尽量只做一类事，说明写清楚，方便以后查历史。

### 3.4 推送到远程仓库

**第一次推送（当前分支叫 main 时）：**

```bash
git push -u origin main
```

若远程默认分支是 `master`，则：

```bash
git push -u origin master
```

**之后每次提交完只需：**

```bash
git push
```

若提示要登录，按 GitHub/Gitee 的提示输入账号密码或 Token；若用 SSH，需先配好 SSH 密钥。

## 四、建议的提交信息示例（本次交付）

可按你实际改的内容选一条或自己写一条：

- `fix: 补充 docker-compose 中 v12-v17 数据库迁移，修复 create_admin 重复 commit，新增线上部署与提交说明文档`
- `chore: 上线前修复与文档 — 迁移补齐、管理员脚本、宝塔部署说明、Git 提交指南`

## 五、常见问题

**Q：`git push` 提示 "rejected" 或 "non-fast-forward"？**  
A：说明远程有新提交，你先拉再推：

```bash
git pull origin main --rebase
git push
```

（若默认分支是 master 就把 `main` 改成 `master`。）

**Q：不小心把 .env 加进去了怎么办？**  
A：从暂存区移除并加入 .gitignore，不要提交：

```bash
git reset HEAD .env
echo ".env" >> .gitignore
git add .gitignore
git commit -m "chore: 确保 .env 被忽略"
# 若 .env 已经提交过，需要从历史里删除，可搜索 "git remove file from history"
```

**Q：想撤销上一次提交但保留修改？**  
A：`git reset --soft HEAD~1`（仅撤销 commit，改动还在）。

按以上步骤即可完成「干净提交并上传到仓库」。提交前务必再跑一遍 `git status` 确认没有敏感文件。

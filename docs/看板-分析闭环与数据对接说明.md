# 看板规则研判与共识分析职责说明

## 一、职责划分（不重复）

- **看板（指挥中心）**  
  - **全币种规则研判**：仅基于 **GET `/api/dashboard/overview`** 返回的 `symbols[]` 做**纯规则引擎**判断，**不调用分析 API**。  
  - 规则：`alert_level` 为 high/critical → 风险；`direction` 非 neutral 且 `confidence >= 0.4` 且 `is_worth_taking` → 可操作；否则观望。  
  - 展示：每个币种一行（名称、最新价、方向、研判结果、置信度），点击行可跳转共识页对该币做深度分析。  
  - 无概览数据时提示在后台启用币种并刷新；提供「深度分析」链接进入共识页。

- **共识分析页**  
  - **单币种深度分析**：用户选交易对、模式后点击「开始分析」，**调用分析 API**，展示完整 AI 报告。  
  - 与看板不重复：看板 = 全币种规则快照；共识 = 单币种深度分析。

## 二、数据来源（无硬编码）

- **看板规则引擎**  
  输入：`overview.symbols`（同上）。  
  实现：`frontend/lib/dashboardRuleEngine.ts`，纯前端函数 `runDashboardRuleEngine(symbols)`。

- **Market Pulse（右侧栏）**  
  来自 **GET `/api/dashboard/overview`** 的 `symbols[]`，每币种 `latest_price`、`direction`，无写死价格。

- **系统状态**  
  来自 **GET `/api/datasources/status`**。

## 三、后端数据流（供对照）

- **概览**  
  `GET /api/dashboard/overview` → 各 symbol 读 Redis `latest_price:{symbol}`、`strategy:latest:{symbol}`、`defense:summary:{symbol}` → 返回 `SymbolOverview`（含 direction、confidence、alert_level、is_worth_taking 等）。  
  看板用该数据跑规则引擎即可，无需再请求分析接口。

## 四、小结

| 项目         | 说明 |
|--------------|------|
| 看板         | 全币种规则研判，不调用 API，仅用 overview 数据 + 规则引擎。 |
| 共识分析     | 单币种深度分析，调用分析 API，与看板职责分离。 |
| Market Pulse | 使用 overview 的 `latest_price`，无硬编码。 |

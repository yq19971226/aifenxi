# 部署与运维备忘（上下文保留）

本文档记录线上部署、排错和运维中的关键约定与命令，供后续对话或接手者快速恢复上下文。

---

## 一、环境与路径

- **线上项目目录**：`/opt/axiom`
- **域名**：`https://axiom123.cc`（无 www，与 Nginx/SSL 一致）
- **仓库**：`https://github.com/yq19971226/aifenxi`，主分支 `master`
- **拉代码或改前端/文案后**：务必**重建 frontend**（见下），否则线上仍是旧包（如缺 `nav.common.guide`、WS 仍用 ws:// 等）。

---

## 二、前端构建与登录/注册

- 前端在**构建时**把 `NEXT_PUBLIC_API_URL`、`NEXT_PUBLIC_WS_URL` 写进静态资源，**改域名或 .env 后必须重建 frontend**。
- `.env` 中**不要**给 `PUBLIC_API_URL` 加 `/api`，应为根域名，例如：
  - `PUBLIC_API_URL=https://axiom123.cc`
  - `NEXT_PUBLIC_WS_URL=wss://axiom123.cc`
- 否则登录请求会变成 `.../api/api/auth/login`，导致 404/Not Found。

**重建前端（拉代码后必做）：**
```bash
cd /opt/axiom
git pull
docker compose -f docker-compose.yml -f docker-compose.prod.yml build --no-cache frontend
docker compose -f docker-compose.yml -f docker-compose.prod.yml up -d frontend
```
说明：项目路径为 `/opt/axiom`，不要用占位符 `/path/to/aifenxi`。

## 三、Nginx 反向代理（宝塔）

- `/api` 代理到 `http://127.0.0.1:8000` 时，**`proxy_pass` 不要写末尾斜杠**：
  - 正确：`proxy_pass http://127.0.0.1:8000;`
  - 错误：`proxy_pass http://127.0.0.1:8000/;`（会去掉 `/api`，后端收到 `/auth/login` 导致 404）
- **`/health` 也需代理到后端**：后台监控页会请求 `https://域名/health`，若 Nginx 只配了 `/api`，会 404。可增加：
  - `location /health { proxy_pass http://127.0.0.1:8000; proxy_http_version 1.1; proxy_set_header Host $host; proxy_set_header X-Real-IP $remote_addr; }`

## 四、管理员密码重置

- 脚本：`backend/scripts/create_admin.py`，已改为使用 `app.core.security.hash_password`（不再依赖 passlib）。
- 在**已运行**的 backend 容器内执行时需带上 `PYTHONPATH=/app`，否则可能 `No module named 'app'`。

**命令：**
```bash
cd /opt/axiom
docker compose -f docker-compose.yml -f docker-compose.prod.yml exec -e PYTHONPATH=/app backend python scripts/create_admin.py
```
- 输入管理员邮箱和新密码（输入时无回显，正常）。
- 若遇「too many clients」，先 `restart postgres backend worker beat` 再执行；或先 `build --no-cache backend` 再 `up -d`，然后用 `exec` 执行脚本（避免 `run` 多占连接）。

## 五、数据库：audit_logs 表

- 数据维护页「数据库表统计」中的 `audit_logs` 表由迁移 `v18_audit_logs.sql` 创建。
- **已有库**（非首次 init）不会自动执行该迁移，需**手动执行一次**建表：

```bash
docker compose -f docker-compose.yml -f docker-compose.prod.yml exec -T postgres psql -U omnimind -d omnimind <<'SQL'
CREATE TABLE IF NOT EXISTS audit_logs (
    id          UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id     TEXT,
    action      TEXT,
    detail      TEXT,
    created_at  TIMESTAMPTZ DEFAULT (now())
);
CREATE INDEX IF NOT EXISTS idx_audit_logs_created_at ON audit_logs (created_at DESC);
CREATE INDEX IF NOT EXISTS idx_audit_logs_user_id ON audit_logs (user_id) WHERE user_id IS NOT NULL;
SQL
```

## 六、注册 500 / 验证码 / 其他 500

- **注册 500**：多为数据库缺字段（如 `referral_code`）。若未执行过 v8 迁移，需在服务器上对已有库执行 v8（为 `users` 增加 referral 相关字段）。
- **其他 500**（如 `/api/auth/register`、`/api/stats/online`）：以 backend 日志为准定位；常见为缺表/缺列、Redis 不可用等。
- 已做容错：注册成功后删 Redis 验证码键失败只打日志；邀请码生成失败、发送验证码时 Redis 不可用会返回 503 并打日志。
- 若仍出现 500，查看 backend 日志定位原因：
  ```bash
  docker compose -f docker-compose.yml -f docker-compose.prod.yml logs backend --tail=200
  ```
  关注 `register failed:` 或完整 Traceback。

## 七、服务器拉代码与全量更新

- 若分支与远程不一致，可直接以远程为准：
  ```bash
  cd /opt/axiom
  git fetch origin
  git reset --hard origin/master
  ```
- 拉取后重建并启动（按需选择）：
  ```bash
  docker compose -f docker-compose.yml -f docker-compose.prod.yml build --no-cache backend
  # 若改过前端/域名
  docker compose -f docker-compose.yml -f docker-compose.prod.yml build --no-cache frontend
  docker compose -f docker-compose.yml -f docker-compose.prod.yml up -d
  ```

## 八、迁移文件缺失导致 Postgres 无法启动

- 若报错挂载某 `.sql` 失败（如 `v15_email_normalize.sql`），说明服务器上缺少该文件。
- 解决：`git reset --hard origin/master` 拉齐代码，或对缺失文件执行 `touch /opt/axiom/backend/migrations/文件名.sql` 再启动。

## 九、若卡片/占位符/用户指南仍未更新

- **卡片**（分享卡进场止损止盈、无点位提示）、**登录/注册邮箱占位符**（应为「请输入邮箱」等）、**用户指南**（英文应为 `/en/guide`）依赖最新前端构建。
- **自查顺序**：
  1. 服务器是否已拉取最新并成功构建：`git log -1 --oneline` 为预期提交；`docker compose ... build --no-cache frontend` 无报错；`docker compose ... up -d frontend` 已执行。
  2. 浏览器强刷（Ctrl+Shift+R）或无痕窗口打开，排除本地与 CDN 缓存。
  3. 用户指南链接已改为带当前语言：英文下应为 `https://域名/en/guide`，不再出现点「用户指南」跳到中文页。
